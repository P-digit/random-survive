# 🎲 랜덤 좌표 생존기

> 지구의 랜덤한 좌표에 떨어져, 기본 물품만 가지고 **한국으로 돌아오는** AI 텍스트 생존 게임

랜덤으로 뽑힌 위도·경도의 **실제 현재 날씨**(Open-Meteo)를 바탕으로, AI 게임 마스터가 그 지역에 어울리는
상황과 이벤트를 만들어 냅니다. 플레이어는 챗봇과 대화하듯 행동을 입력하며 살아남고, 돈을 벌고,
교통수단을 갈아타며 서울까지 돌아와야 합니다.

## 주요 기능

- **랜덤 낙하** – 지구 표면에서 균일하게 좌표를 뽑고, 고도 API로 바다를 걸러 육지에만 떨어집니다.
- **실제 기후 반영** – 최근 1년간의 기온·강수량 기록으로 그 좌표의 기후대(사막, 열대우림, 냉대 등 8종)와 지금 계절을 판별해 지형·서술·이미지에 반영합니다.
- **실제 날씨 반영** – 기온·체감온도·바람·강수에 따라 수분 소모, 체력 감소, 위험도가 달라집니다.
- **AI 게임 마스터** – 자유 입력한 행동을 판정하고 서술합니다. 수치 변경은 전부 Tool Calling으로만 합니다.
- **ML 위험도 예측** – 날씨와 몸 상태로 위험 등급(안전/주의/위험)을 예측하고, 등급이 높을수록 위험한 이벤트가 자주 발생합니다.
- **생존 지식 RAG** – 뱀에 물렸을 때, 저체온증, 여권 분실 등 생존 지식 문서를 검색해 올바른 대처에 좋은 결과를 줍니다.
- **극한 지형** – 설원·사막·고산·열대우림에서는 지형별로 소모와 피해가 커집니다. 불·쉘터 여부가 생사를 가릅니다.
- **시간의 흐름** – 모든 행동에 시간이 흐르고, 흐른 시간만큼 예보를 따라 날씨도 바뀝니다 (밤에는 추워집니다).
- **대형 이벤트(기회)** – 구조 헬기, 장거리 트럭, 영사관 지원금, 한국행 화물선 같은 큰 기회가 가끔 찾아옵니다. 받아들이면 엔진이 결과를 굴립니다. 15~30% 확률로 강도, 사기, 폭풍 같은 나쁜 결과가 나옵니다.
- **장면을 따라가는 이미지** – 오두막에 들어가거나 시장으로 옮기는 등 장면이 바뀔 때마다 그 장소(실내 포함)를 새로 그립니다.
- **그림과 서술의 일치** – 게임 마스터가 밝힌 대상만 그리게 하고, 그려진 이미지를 다시 Vision으로 읽어 "화면에 보이는 것"을 게임 마스터에게 알려 줍니다. 그림에 보이는 건물은 게임에서도 존재합니다.
- **중요 알림** – 기회, 위험 이벤트, 이동, 기회의 결과, 사망·귀환은 대화창에 색이 다른 상자로 표시됩니다.
- **자동 저장과 이어하기** – 매 턴 `saves/autosave.json`에 저장되고, 프로그램을 껐다 켜도 이어서 할 수 있습니다.
- **억지 방지** – "텔레포트기를 줍는다"처럼 상황에 맞지 않는 행동은 실패합니다. 플레이어의 입력은 '시도'일 뿐이고, 무엇이 존재하는지는 게임 마스터와 엔진이 판정합니다.
- **게임 UI** – 체력바, 남은 거리, 위험도 게이지, 소지품, 교통수단 요금표를 보여 주는 상태창(HUD). 수치가 변하면 초록(+)·빨강(-)으로 표시됩니다.

## 수업 내용과의 연결

| 과정 | 배운 내용 | 프로젝트에서 쓰인 곳 |
|---|---|---|
| LLM 01. OpenAI API | Responses API, `previous_response_id` 멀티턴, Gradio | `survival/gamemaster.py`, `app.py` |
| LLM 02. Multimodal | Images API (`gpt-image-1-mini`, Base64 디코딩), Vision(이미지 → 텍스트) | `survival/imagegen.py` |
| LLM 03. Tool / MCP | Function Calling, 외부 API 호출, FastMCP 서버 | `survival/tools.py`, `survival/weather.py`, `survival/climate.py`, `mcp_server.py` |
| LLM 04. RAG | Chunking → Embedding → ChromaDB → Retrieval | `survival/knowledge.py`, `data/survival_guide.txt` |
| ML 01~04 | `train_test_split`, 분류, 평가 지표, 앙상블(RandomForest) | `survival/risk_model.py` |

## 실행 방법

Python 3.10 이상이 필요합니다.

```bash
git clone https://github.com/P-digit/random-survive.git
cd random-survive

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt             # 필수 패키지만 (빠름)
# pip install -r requirements-optional.txt  # 선택: ChromaDB, MCP 서버, 테스트

cp .env.example .env             # Windows: copy .env.example .env
# .env 파일을 열어 OPENAI_API_KEY 를 입력

python app.py
```

터미널에 표시되는 주소(기본 `http://127.0.0.1:7860`)를 브라우저로 열면 게임이 시작됩니다.

> `chromadb`는 설치가 오래 걸려 선택 사항으로 분리했습니다. 없으면 같은 임베딩을 numpy로 비교하는
> 방식으로 RAG가 동작하고, 설치하면 자동으로 ChromaDB를 사용합니다.

> 장면 이미지 생성은 한 장에 10~30초가 걸리고 비용이 듭니다. 화면의 체크박스로 끌 수 있습니다.

### 그 밖의 명령어

```bash
python -m survival.risk_model    # 위험도 모델만 따로 학습하고 평가 결과 보기
python -m pytest                 # 게임 엔진 테스트 (네트워크·API 키 불필요)
fastmcp list mcp_server.py       # MCP 서버의 툴 목록 확인
```

## 게임 규칙

| 항목 | 내용 |
|---|---|
| 시작 물품 | 물 1L, 에너지바 2개, 라이터, 다용도 칼, 여권, 스마트폰(배터리 30%), $50 |
| 승리 | 서울 반경 60km 안에 도착 |
| 패배 | 체력 0 |
| 시간 | 모든 행동은 시간이 흐릅니다. 포만감·수분·기력이 줄고, 0이 되면 체력이 깎입니다. 줄어드는 속도는 `survival/config.py`의 `VITALS_DRAIN`(기본 1.6배)으로 조절합니다 |
| 시간 | 취침 6~8시간, 일하기 4~8시간 등 행동에 맞는 시간이 흐릅니다. GM이 시간을 빠뜨리면 엔진이 입력 문장에서 추정해 반영합니다 |
| 날씨 | 야생에서 체감 0°C 이하 또는 35°C 이상이면 시간당 체력이 깎이고, 극단적일수록 더 크게 깎입니다. 불·쉘터가 있으면 피해가 1/4로 줄어듭니다 |
| 장소 | 야생 → 마을 → 도시. 이동할 때마다 엔진이 확률로 결정합니다 |
| 턴 | 한 턴에 행동 하나. 이동과 시간 경과는 한 턴에 한 번만 반영됩니다 |
| 소지품 | 들고 다닐 수 있는 물건만 들어갑니다(오두막·오아시스·차량 등은 거부). 먹거나 마신 것은 사라지고, `에너지바 2개`는 하나씩 줄어듭니다 |
| 기회 | 매 턴 10% 확률, 8턴 동안 없으면 반드시 발생. 나온 다음 턴까지 받아들이지 않으면 사라집니다. 현재 장면에 맞는 것만 나오고(실내에서는 지나가는 차량 등이 나오지 않음), 받아들이면 15~30% 확률로 나쁜 결과가 됩니다 |
| 예약 | 버스·기차·배·비행기 표는 미리 사 둘 수 있습니다. 표는 저장되어 탈 때까지 유지되고, 타면 요금 없이 탑승한 뒤 소지품에서 사라집니다 |
| 이동 | 이동은 한 턴에 도착까지 끝납니다. 탈것 안에서의 턴은 없습니다. 비행기는 한국 직항뿐입니다 |
| 저장 | 매 턴 자동 저장. 사망하거나 귀환하면 저장 파일이 지워집니다. "새로 낙하"를 누르면 이전 저장을 덮어씁니다 |

| 이동 수단 | 이용 장소 | 최대 거리 | 요금 |
|---|---|---|---|
| 도보 | 어디서나 | 30km | 무료 |
| 히치하이킹 | 어디서나 | 250km | 무료 (40% 확률로 실패) |
| 버스 | 마을·도시 | 600km | $2 + km당 $0.05 |
| 기차 | 도시 | 1,500km | $5 + km당 $0.07 |
| 배 | 도시 | 3,000km | $30 + km당 $0.06 |
| 비행기 | 도시 | 제한 없음 | $250 + km당 $0.10 |

육로 이동(도보·히치하이킹·버스·기차)은 바다에 막히면 실패합니다.

### 극한 지형 (야생에 있을 때만 적용)

| 지형 | 환경 위험 | 도보 속도 | 히치하이킹 성공 | 마을 발견 |
|---|---|---|---|---|
| 설원 | 포만감 소모 1.5배, 기력 소모 1.3배, 혹한 피해 | 2.5km/h | 25% | 12% |
| 고산지대 | 기력 소모 1.6배, 3,500m 이상 고산병 | 2.5km/h | 25% | 12% |
| 사막 | 낮 수분 소모 2배, 폭염 피해, 밤 추위 | 3km/h | 25% | 10% |
| 열대우림 | 수분 1.4배·기력 1.3배, 벌레·감염으로 체력 감소 | 2.5km/h | 30% | 18% |
| 초원 | 수분 소모 1.15배 | 4km/h | 55% | 30% |
| 온대림 | 없음 | 4km/h | 60% | 30% |

극한 지형에서는 돌발 이벤트 판정도 위험 등급을 한 단계 올려서 굴립니다.

## 동작 구조

```
플레이어 입력
   │
   ▼
[엔진] 턴 시작 ── ML 모델로 위험 등급 예측 ── 등급에 따라 돌발 이벤트 추첨 ── 가끔 대형 이벤트(기회)
   │
   ▼
[LLM] 현재 상태 + 이벤트 + 플레이어 행동을 받아 툴 호출을 요청
   │      advance_time / update_status / update_inventory / travel / buy_ticket / set_scene
   │      accept_offer / reject_event / search_survival_guide
   ▼
[엔진] 툴 실행 (규칙 검증, 수치 범위 제한, Open-Meteo 재조회, RAG 검색)
   │
   ▼
[LLM] 툴 결과를 보고 최종 서술 + 추천 행동 3개 생성
   │
   ▼
[UI] 대화창·상태창 갱신 → 자동 저장 → 장소·낮밤·날씨(비/눈/폭풍)가 바뀌었으면 장면 이미지 재생성
```

**설계 원칙: 숫자는 엔진이, 이야기는 LLM이.** LLM이 체력이나 돈을 마음대로 지어내지 못하도록
모든 수치는 `survival/state.py`의 규칙을 거쳐서만 바뀌고, 한 번에 바꿀 수 있는 범위도 제한됩니다.

│   ├── events.py           # 지형 판별, 지형별 돌발 이벤트

## 사용한 외부 서비스

- [OpenAI API](https://platform.openai.com/) – 게임 마스터, 이미지 생성, 임베딩 (API 키 필요)
- [Open-Meteo](https://open-meteo.com/) – 날씨, 고도, 과거 기후 기록 (키 불필요, 비상업적 용도 무료)
- [OpenStreetMap Nominatim](https://nominatim.org/) – 좌표 → 지명 (키 불필요, 초당 1회 이하로 사용)

## 한계와 개선 계획

- **위험도 모델은 합성 데이터로 학습했습니다.** 실제 조난 데이터가 아니라 생존 상식에 기반한 규칙에 노이즈를 섞어 만든 데이터이므로, 모델은 그 규칙을 근사할 뿐입니다 (테스트 정확도 약 0.82). 플레이 로그를 모아 실제 사망/생존 결과로 다시 학습하는 것이 다음 목표입니다.
- 날씨 예보는 4일치만 받아오므로, 한 곳에 그보다 오래 머물면 마지막 예보 값이 유지됩니다.
- 기후 분류는 쾨펜 분류를 단순화한 것이고 최근 1년 기록만 씁니다. 그해 날씨가 유별났다면 실제 기후대와 다르게 나올 수 있습니다. 기록을 못 가져오면 위도와 현재 날씨로 추정합니다.
- 그림과 서술의 일치는 이미지 모델과 Vision 모델에 의존합니다. 그림 속 작은 대상까지 모두 읽어내지는 못합니다.
- 억지 행동 방지는 프롬프트 규칙과 엔진의 소지품 검사(금지어 목록)를 함께 씁니다. 금지어 목록에 없는 기발한 억지는 게임 마스터의 판단에 달려 있습니다.
- 오래된 세이브는 OpenAI 쪽 대화 기록이 만료될 수 있습니다. 이때는 최근 대화 6개를 줄거리로 넣어 새 대화로 이어갑니다.
- 이동은 항상 서울 방향 대권 경로를 따릅니다. 국경, 비자, 실제 도로망은 반영하지 않습니다.
- 계획 중: 음성 내레이션(TTS), 지도 표시, 플레이 기록 저장과 랭킹, 클러스터링(K-Means)을 이용한 기후대 분류.
